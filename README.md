# Frontier Engine

A from-scratch, procedural first-person outdoor sandbox written in C++20. The
goal is the *feel* of mid-2000s outdoor engines (large terrain, directional sun,
shadows, distance fog, wind-blown foliage, a debug overlay) implemented with a
modern, compact, readable codebase — **no CryEngine code, shaders, assets,
branding or UI are used**. Every mesh, texture and shader in the world is
generated by this repository.

```
                        .  .
                  .      |      .          Frontier Engine 0.1.0
              ___|___    |    ___|___      C++20 · CMake · SDL2 · OpenGL 4.5 · GLM · Dear ImGui
```

## Quick start

Two commands and you are walking around a generated lake. Everything needed is
in this repository except SDL2, which CMake can fetch for you.

### Windows 10/11

Requirements: CMake 3.20+ and a C++20 compiler ("Desktop development with C++"
from Visual Studio 2022 or the Build Tools are enough; MinGW works too).

```bat
:: from a terminal in this folder (PowerShell: .\scripts\build_windows.bat)
scripts\build_windows.bat
build\Release\frontier.exe
```

The script configures with `-DFRONTIER_FETCH_SDL2=ON` (SDL 2.28.5 is downloaded
and built), builds in Release, and copies `assets/` and `SDL2.dll` next to the
executable. Use `scripts\run_windows.bat` to launch it with the console window
kept open (it prints the exit code and any error message). With the MinGW/Ninja generator the binary is `build\frontier.exe`.
The manual equivalent is:

```bat
cmake -S . -B build -DFRONTIER_FETCH_SDL2=ON
cmake --build build --config Release
```

**No compiler on your machine?** Every push is built by GitHub Actions on
Ubuntu and Windows. Open the **Actions** tab, pick the latest `build` run and
download the `frontier-windows-x64` (or `frontier-linux-x64`) artifact, unzip it
and run `frontier.exe` / `frontier`. The folder already contains `SDL2.dll` and
`assets/`.

### Linux

```bash
sudo apt install build-essential cmake libsdl2-dev     # Debian / Ubuntu
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"
cd build && ./frontier
```

No SDL2 development package available? Add `-DFRONTIER_FETCH_SDL2=ON` to the
configure step and CMake downloads and builds SDL2 itself.

```bash
# equivalent, using the bundled presets
cmake --preset linux        # or linux-fetch to build SDL2 from source
cmake --build --preset linux
```

The console (and `frontier.log`) prints, in order:

and then a window with a lake, a shoreline of grass and reeds, rolling hills,

The mouse is captured: `WASD` walks, `Space` jumps, `Shift` sprints, `Esc`
releases the mouse, `F1` toggles the panel.

### Verify your machine before playing

`--selftest` opens the window, renders 45 frames through the complete pipeline
(including the ImGui overlay), reads the framebuffer back and checks the result:

```bash
./frontier --selftest        # Windows: frontier.exe --selftest
```

```
Self-test image: mean luminance 0.284, contrast 0.161, black pixels 0.0%, sky 0.512 vs ground 0.091.
Self-test totals: 12 draw calls, 1441783 triangles, 17386 visible instances, 34541 culled.
  [PASS] frame buffer readable
  [PASS] no OpenGL errors
  [PASS] image is neither black nor blown out
  [PASS] image has contrast (not a flat colour)
  [PASS] most pixels are not black
  [PASS] sky and ground regions differ
  [PASS] geometry was drawn
Self-test PASSED: the renderer produced a varied, non-black frame.
```

The frame it judged is saved to `screenshots/selftest.ppm` (convert with
ImageMagick or ffmpeg). Exit code is 0 on success and 3 on failure, so it can be
scripted. If it fails, the log says which check failed and the troubleshooting
section lists what to try.

If the window does not appear, or it appears black, see
[Troubleshooting](#troubleshooting); `--safe-mode` turns off MSAA, HDR and bloom
and shrinks the world, which is the first thing to try on an older GPU.

## Status and verification

The engine is a complete, runnable vertical slice: it builds with CMake, links,
starts, generates a world, simulates the player and renders through the full
pipeline on a machine with an OpenGL 4.5 driver.

What was verified in the development environment (a headless Linux container
with no GPU, no libGL and no display):

| Check | Result |
| --- | --- |
| `cmake` configure + full build | **passes** (GCC 12.2, CMake 3.28, `-Wall -Wextra -Wpedantic`) |
| Link (SDL2 + vendored ImGui/GLM) | **passes** |
| Headless world + simulation (`--headless`) | **passes** for multiple seeds and configurations |
| Shader `#include` expansion via the runtime loader | **passes** (15/15 sources expand, checked inside `--headless`) |
| All 15 shader stages compile (`glslangValidator`) | **passes** |
| All 9 vertex/fragment program pairs link (`glslangValidator -l`) | **passes** |
| SDL2 fetched and built by `FRONTIER_FETCH_SDL2=ON` | **passes** (SDL 2.28.5 built from source, binary runs) |
| CMake presets (`linux-fetch`) configure/build/run | **passes** |
| Windows build with MSVC 2022 + fetched SDL2 (`windows-latest`) | **passes** in GitHub Actions, including `--headless=60` |
| Linux build with fetched SDL2 (`ubuntu-latest`) | **passes** in GitHub Actions, including `--headless=60` |
| Ready-to-run CI artifacts | published by the workflow (`frontier-windows-x64`, `frontier-linux-x64`) |
| `--selftest` framebuffer checks | thresholds are unit-checked against synthetic frames in `--headless`; the GPU path needs a real driver, so it cannot run in this container |
| Render target fallbacks (MSAA → 1x → LDR) | implemented defensively; the code paths are not reachable without a GL driver |
| Windowed OpenGL start-up | **cannot be exercised here** — the container has no GL driver; the engine exits with a clear error instead of crashing |
| Visual output / screenshots | not captured for the same reason |

The build is verified on three toolchains (GCC 12, MSVC 2022 via GitHub
Actions, and the no-CMake fallback script). The rendering code (framebuffers,
extension-free GL loader, instancing, shader uniforms) is compile- and
shader-validated, but has not been pixel-verified in this container. On a normal desktop the expected flow is
`cmake --build build && cd build && ./frontier`.

Start-up is deliberately defensive: the engine prints the GL vendor, renderer,
version and profile, refuses to run on a driver older than 4.5 with an
explanation instead of a black window, clamps the shadow-map and MSAA requests
to the driver limits, and falls back from multisampled HDR to single-sample HDR
to LDR if a render-target format cannot be created.

## Features

### Engine core
- Deterministic main loop with high-resolution timing, smoothed FPS statistics
  and a fixed-step accumulator helper.
- Thread-safe logging with levels, timestamps, source locations and optional
  file tee (`frontier.log`).
- Layered configuration: built-in defaults → config file → command line,
  with validation/clamping of every value.
- SDL2 window with an OpenGL 4.5 core context, resize and borderless
  fullscreen, VSync toggle.
- Input layer with logical actions, primary/secondary bindings, relative mouse
  capture and per-frame pressed/down/released queries.
- First-person camera with pitch clamping, FOV control, view/projection
  matrices, view-frustum extraction and subtle head bob.

### Renderer
- Forward renderer on OpenGL 4.5 Core, no deprecated APIs.
- Runtime GL loader — the engine links against no GL library and needs no GL
  development headers (only `SDL_GL_GetProcAddress`).
- Directional sun shadows: fitted orthographic light frustum, texel snapping,
  2048² (configurable) depth map, 3×3 PCF with slope-aware bias.
- HDR scene target (RGBA16F) with optional 2×/4×/8× MSAA and resolve.
- Atmospheric sky: procedural Rayleigh-ish gradient, sun disk and glow, moon,
  twinkling stars, FBM cloud deck, dusk horizon tint.
- Terrain shading with slope/height material blending (grass, soil, rock,
  shoreline sand, snow), procedural detail textures and height/distance fog.
- Instanced foliage: 5 vegetation families, 3 LODs each, per-instance colour
  and wind phase, vertex-shader wind with gusting, double-sided cards.
- Water: Gerstner-style waves, depth-based colour from the terrain height map,
  fresnel sky reflection, sun specular, shoreline foam, whitecaps.
- Post-processing: bright-pass + separable Gaussian bloom, ACES filmic tone
  mapping, exposure, vignette, sRGB encode.
- Debug: wireframe mode, pass timings, draw-call/triangle/instance counters,
  PPM screenshot output.

### World
- 900 m × 900 m procedural heightfield (256² quads by default, configurable):
  rolling hills, masked ridged mountain ranges, a lake basin, a river valley,
  and an outer rim that frames the map.
- CPU heightfield is independent of GPU resources: query height, slope and
  water depth anywhere; used for spawn selection, collision and placement.
- Procedural lake surface with real depth tint queried from the terrain height
  texture.
- Forest with conifers and broadleaf trees, boulders, shrubs and grass clumps;
  placement respects water level, slope, clustering noise and the spawn area.
- Time-of-day system: continuous sun arc, sunrise/sunset colours, moonlight,
  star field, dynamic ambient/fog colours, adjustable day length and time
  scale, pause.
- Player controller: WASD, sprint, walk, jump, gravity, slope blocking,
  downhill surface adherence, buoyancy/swimming, respawn, head bob.

### Tooling
- `--glinfo` prints the SDL video driver, displays, context attributes, GL
  vendor/renderer/version, profile and driver limits, then exits — the fastest
  way to diagnose "it will not start" on a particular machine.
- `--selftest` renders the full pipeline including the ImGui overlay, reads the
  back buffer and checks luminance, contrast and draw-call statistics, writing
  `screenshots/selftest.ppm` and exiting 0/3.
- `--headless` mode runs world generation, placement, time of day and player
  physics with no window and no GPU — ideal for CI and for validating the
  simulation on servers. It also expands every shader source (and its
  `#include`s) through the same loader the renderer uses, and fails with exit
  code 3 if any assertion — spawn, heightfield, movement, time, vegetation,
  frustum culling or shader assets — does not hold.
- `scripts/validate_shaders.py` expands the engine's `#include` convention and
  validates every shader stage/program with `glslangValidator`.
- `scripts/build_no_cmake.sh` fallback build for environments without CMake.
- ImGui debug/tuning panel with live performance, world, render, player and
  controls pages.

## Requirements

| Dependency | Minimum | Notes |
| --- | --- | --- |
| C++ compiler | C++20 | GCC 11+, Clang 14+, MSVC 19.29+ |
| CMake | 3.20 | primary build system |
| SDL2 | 2.0.18 (developed with 2.28.5) | window, input, GL context, proc-address loading |
| OpenGL | **4.5 Core** | NVIDIA/AMD/Intel drivers on Windows and Linux |
| GLM | 0.9.9.8 | vendored in `third_party/glm` |
| Dear ImGui | 1.91.0 | vendored in `third_party/imgui` (core + SDL2/OpenGL3 backends) |
| Khronos `glcorearb.h` | current | vendored in `third_party/gl` (types/enums only) |

**Platform support:** Linux (X11/Wayland with a GL 4.5 driver) and Windows
(MSVC or MinGW). macOS is *not* supported because Apple caps OpenGL at 4.1;
the engine intentionally requests a 4.5 core profile.

No OpenGL development package is required: the renderer resolves all entry
points at runtime through SDL. This is why the build only needs SDL2's headers
and library.

## Build

### Linux

```bash
# Debian / Ubuntu
sudo apt install build-essential cmake libsdl2-dev

# Fedora
sudo dnf install gcc-c++ cmake SDL2-devel

# Arch
sudo pacman -S base-devel cmake sdl2

cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"
```

If SDL2 lives in a non-standard prefix:

```bash
cmake -S . -B build -DCMAKE_PREFIX_PATH=/opt/sdl2
# or with a raw prefix containing include/SDL2 and lib/
cmake -S . -B build -DFRONTIER_SDL2_ROOT=/opt/sdl2
```

### Windows (MSVC or MinGW)

```bat
:: easiest: let CMake download and build SDL2
cmake -S . -B build -DFRONTIER_FETCH_SDL2=ON
cmake --build build --config Release

:: or use an SDL2 development package you already have
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DCMAKE_PREFIX_PATH=C:\SDL2
cmake --build build --config Release
```

`scripts\build_windows.bat` does the first variant end to end. The build copies
`SDL2.dll` and `assets/` next to the executable, so the game can be started by
double-clicking `build\Release\frontier.exe`.

Point CMake at an SDL2 install with `-DCMAKE_PREFIX_PATH=C:\SDL2` (the directory
that contains `lib\cmake\SDL2`) or with `-DFRONTIER_SDL2_ROOT=C:\SDL2`.

### Presets

`CMakePresets.json` contains three configure/build presets:

| Preset | Use |
| --- | --- |
| `linux` | system SDL2, Release |
| `linux-fetch` | download and build SDL2, Release |
| `windows` | Visual Studio/MinGW, SDL2 fetched, Release configuration |

```bash
cmake --preset linux-fetch && cmake --build --preset linux-fetch -j
```

### Build options

| Option | Default | Meaning |
| --- | --- | --- |
| `FRONTIER_WARNINGS_AS_ERRORS` | `OFF` | add `-Werror` / `/WX` |
| `FRONTIER_USE_SYSTEM_GLM` | `OFF` | use `find_package(glm)` instead of the vendored headers |

| `FRONTIER_FETCH_SDL2` | `OFF` | download and build SDL 2.28.5 when SDL2 is not found |

The post-build step copies `assets/` next to the executable, so `build/frontier`
can be launched from any directory.

### Without CMake (fallback)

```bash
SDL2_ROOT=/path/to/sdl2 ./scripts/build_no_cmake.sh
# or with SDL2 installed system-wide:
./scripts/build_no_cmake.sh
```

This compiles the same translation units with `g++ -std=c++20` and writes the
binary and assets to `build/`.

### Validate shaders (optional)

```bash
python3 scripts/validate_shaders.py --glslang /path/to/glslangValidator
```

The script expands `#include "..."` the same way the engine's shader loader
does, validates each stage, and reports a per-shader summary.

## Run

```bash
cd build
./frontier
```

The engine starts at the shoreline of a generated lake, captures the mouse and
shows the debug panel. Press `Esc` to release the mouse (click the viewport to
capture it again), `F1` to hide the panel.

Useful launch variants:

```bash
./frontier --seed=42 --time=18.4                 # golden-hour shoreline
./frontier --fullscreen --vsync=0                # borderless, uncapped
./frontier --trees=1500 --grass=120000           # denser forest
./frontier --shadow-size=4096 --view-distance=1200
./frontier --config=my-world.ini
./frontier --headless=300                        # CI smoke test, no GPU required
./frontier --help
```

### Frame loop

```
poll SDL events ─► ImGui backend ─► Input::NewFrame
      │
      ▼
Update(dt)
  ├─ gameplay hotkeys (F1…F12, R, G, [ ])
  ├─ sync player settings / FOV / mouse sensitivity
  ├─ Player::ApplyMouseLook → Player::Update (physics, collision, swimming, bob)
  ├─ build view frustum from the camera
  └─ World::Update (time of day → lighting, wind, vegetation visibility)
      │
      ▼
DebugUI::NewFrame → DebugUI::Draw → apply UI actions (respawn/regenerate/…)
      │
      ▼
Renderer::Render
  ├─ shadow pass (terrain + instanced casters)
  ├─ scene target: sky → terrain → foliage → water
  ├─ resolve MSAA
  └─ bloom → ACES tone map → default framebuffer
      │
      ▼
ImGui render → SDL_GL_SwapWindow
```

`World` deliberately separates CPU generation (`Generate`) from GPU upload
(`BuildRenderResources`). Headless mode uses the former; the windowed path uses
both. Vegetation placement, spawn selection, collision and statistics therefore
work without a graphics driver.

## Renderer pipeline

| Shader | Pass | Notes |
| --- | --- | --- |
| `shadow.vert` / `shadow.frag` | sun shadow | depth-only, terrain |
| `shadow_instanced.vert` | sun shadow | per-instance transforms + matching wind sway |
| `sky.vert` / `sky.frag` | sky | fullscreen ray reconstruction, sun/moon/stars/clouds |
| `terrain.vert` / `.frag` | opaque | slope/height material blend, detail maps, shadow, fog |
| `foliage.vert` / `.frag` | opaque instanced | wind, per-instance tint, translucency, fog |
| `water.vert` / `.frag` | transparent | Gerstner waves, depth tint, fresnel, foam |
| `fullscreen.vert` + `bloom_threshold.frag` | bloom | bright pass into half-res target |
| `bloom_blur.frag` | bloom | 9-tap separable Gaussian, two iterations |
| `post.frag` | post | bloom combine, exposure, ACES, vignette, gamma |

Details:
- Shadow map is a 24-bit depth texture with PCF 3×3, slope-scaled bias and a
  light frustum fitted to a ~170 m radius around the camera (clamped by
  `viewDistance`).
- The scene target is RGBA16F (or RGBA8 with `--no-hdr`) with optional MSAA;
  the MSAA draw buffer is blitted into a sampleable resolve texture.
- Detail textures are generated on the CPU at start-up (512² each) from the
  engine's own noise: grass/dry-grass/soil variation, cracked rock, pebbly soil.
- Texture unit assignments: 0–2 terrain detail, 3 shadow map, 4 terrain height
  field (water depth). The post pass uses 0 = scene, 1 = bloom.
- GL state is fully re-established per pass (depth mask, blending, culling,
  polygon mode), so toggling wireframe/water/foliage mid-frame is safe.

### Material model

Surfaces are described by a small set of shader-level materials rather than a
generic uber-shader. Each material controls its own albedo sources, roughness
approximation, sidedness and blending:

| Material | Albedo | Shading | Sidedness / blend |
| --- | --- | --- | --- |
| Terrain | vertex macro colour × 3 procedural detail maps blended by slope/height, shoreline sand and altitude snow masks | Lambert + wrapped sun + ambient sky/ground, height fog | opaque, back-face culled |
| Foliage | vertex colour × per-instance tint × procedural leaf variation | Lambert + translucency term + ambient, height fog | double-sided, opaque |
| Water | depth-graded body colour (terrain height texture) + fresnel sky reflection + sun specular + foam | analytic Gerstner normals, semi-transparent | double-sided alpha blend, depth-write off |
| Sky | procedural gradient, sun/moon disks, clouds, stars | emissive, no lighting | fullscreen, no depth |
| Shadow caster | — | depth only | both faces |

Material parameters (fog density/falloff, exposure, bloom, detail directions via
world space, tint ranges) are uniform-driven and exposed through the config and
the ImGui panel. Objects share meshes and materials through instancing, so a
forest of 900 trees costs one draw call per visible LOD bucket instead of 900.

## World generation

**Terrain.** For each heightfield sample the engine combines:
- large-scale rolling FBM hills;
- ridged noise masked by a low-frequency field to form distinct mountain
  ranges;
- fine detail noise;
- a smooth radial basin creating the lake, plus a carved river valley;
- a rising rim near the map border to hide the world edge.

Default results for seed 1337: 900 m across, 257² samples, ~131 k triangles,
heights from −28.8 m to +48.8 m, water at 0 m. The heightfield feeds:
1. the terrain mesh and per-vertex macro colour (grass/soil/rock/sand/snow),
2. bilinear height queries for collision and placement,
3. an R32F height texture sampled by the water shader for depth tint and foam,
4. spawn selection: preferring a flat, dry spot near the shoreline (within ~150 m),
   with a clear view over the lake.

**Vegetation.** Each family is generated independently with rejection sampling:
- conifers and broadleaf trees avoid water and slopes steeper than ~39°, and
  follow low-frequency forest-density noise;
- boulders favour slopes and shorelines;
- grass and shrubs require dry, gentle ground and clump density noise.

Default placement (seed 1337): 564 conifers, 336 broadleaf trees, 320 rocks,
48 404 grass clumps and 2 303 shrubs — 51 927 instances total. One-frame LOD
thresholds:

| Family | LOD 0 | LOD 1 | LOD 2 (cards) | Casts shadows |
| --- | --- | --- | --- | --- |
| Conifers | 150 m | 380 m | 900 m | LOD 0–1 |
| Broadleaf | 130 m | 330 m | 900 m | LOD 0–1 |
| Rocks | 90 m | 240 m | 620 m | LOD 0–1 |
| Grass | 32 m | 78 m | 135 m | no |
| Shrubs | 55 m | 120 m | 220 m | LOD 0–1 |

Instances are distance-sorted into LOD buckets and frustum-culled on the CPU;
only survivors are uploaded and drawn with `glDrawElementsInstanced`. Culling
is skipped when the camera has not moved/turned, and stats are reported in the
panel and the log.

**Wind.** A slowly rotating wind direction with gusting strength is passed to
the foliage and shadow shaders. Sway weight is encoded per vertex (0 at trunk
or blade base, 1 at tips) and each instance carries a phase offset, so motion is
coherent within a plant but decorrelated across the field.

**Time of day.** The sun follows a tilted arc (06:00 sunrise, 12:00 high sun,
18:00 sunset). Colour/intensity are derived from elevation (warm horizon, white
noon), with a separate moonlight term at night. Ambient sky/ground, fog colour,
star and cloud factors follow. Days default to 24 real minutes and can be paused
or rescaled from the panel.

## Assets, shaders and originality

- **No external art.** There are no image, mesh or sound files in the
  repository. Terrain, rocks, trees, grass, cards and the fullscreen triangle
  are built in `GeometryBuilder.cpp`; detail textures are generated in
  `Texture.cpp`; the lake is a tessellated grid; the sky is a shader.
- **No CryEngine content.** All GLSL, geometry, naming, UI layout and tuning
  are original to this repository. The project does not link, copy or
  re-implement CryEngine code and uses no Crytek trademarks or assets. “CryEngine
  2-era” in this README describes the *style of scene* (outdoor terrain, sun,
  foliage), not a technical dependency.
- **Shader `#include`.** GLSL has no standard include mechanism, so the engine's
  `Shader::LoadFromFiles` expands `#include "relative/path.glsl"` recursively,
  relative to the including file, with cycle/depth protection. The same logic is
  duplicated in `scripts/validate_shaders.py` so offline validation matches the
  runtime behaviour.
- **Third-party code** is limited to SDL2, GLM, Dear ImGui and Khronos headers;
  their licenses are retained alongside the sources.

## Known limitations

These are deliberate scope choices for a compact, verifiable implementation:

- **Collision is heightfield-only.** Trees, rocks and shrubs are not solid;
  there is no capsule-vs-mesh collision, no climbing and no step-up over props.
  Steep slopes simply block horizontal movement.
- **Water is a single plane.** Waves are vertex-displaced with an analytic
  normal; reflections are approximated by sky/fog colours, with no
  screen-space or planar reflections and no refraction. Swimming is a simple
  buoyancy model.
- **One terrain mesh.** Terrain has no chunking, quadtree LOD or occlusion
  culling — it is a single 131 k-triangle draw call. At 1024 quads per side the
  mesh becomes heavy; the default 256 is the intended range.
- **Shadows are camera-local.** A single shadow map covers roughly 170 m around
  the player; distant terrain is unshadowed and casters outside the view
  frustum do not contribute shadows. No cascaded shadow maps.
- **Foliage is static aside from wind.** Placement is deterministic per seed but
  there is no growth, destruction, streaming or persistence; regenerating a
  world discards edits (there are none).
- **No audio, particles, animation, physics bodies, save games, networking or
  scripting.** The project is an outdoor rendering/exploration sandbox.
- **Sky and fog are artist-driven approximations**, not a physically based
  atmosphere: single-layer FBM clouds, no time-varying weather, no
  aerial-perspective multi-scattering.
- **Display output is SDR.** HDR is used internally for tone mapping; the
  default framebuffer is not an HDR swapchain, and sRGB encoding is applied
  manually in the post shader.
- **OpenGL 4.5 is mandatory.** There is no GL 3.3/ES fallback, which rules out
  macOS (4.1 cap) and older integrated GPUs.
- **Frame pacing relies on VSync.** With VSync disabled the loop is uncapped;
  there is no separate frame limiter.
- **No gamepad support**, no rebinding UI (bindings are code-driven in
  `Input::Initialize`).

## Troubleshooting

**`SDL2 was not found` at configure time.**
Install `libsdl2-dev` (Debian/Ubuntu) / `SDL2-devel` (Fedora) / `brew install sdl2`
(macOS, for reference only), or pass `-DFRONTIER_SDL2_ROOT=/path/to/sdl2` /
`-DCMAKE_PREFIX_PATH=...`.

**Double-clicking `frontier.exe` seems to do nothing.**
Nothing is *drawn* until a window is created, so a start-up failure looks like
"nothing happened" — the console window closes the moment the process exits.
Three things make that visible now:

1. run `run.bat` (in the CI artifact, or `scripts\build_windows.bat` output)
   instead of the exe: it keeps the console open and prints the exit code;
2. any failed start raises a message box naming the last error and the log path;
3. the log is always written next to the executable (`frontier.log`).

If there is no message box and no log at all, no code ran: the executable was
blocked (antivirus/SmartScreen — allow it), or it is missing `SDL2.dll` and
`assets\` from the same folder. To see the real output, start it from a
terminal:

```bat
cd C:\path\to\frontier
.\frontier.exe
echo exit code: %ERRORLEVEL%
```

**`SDL2.dll was not found` (Windows).**
The executable needs `SDL2.dll` beside it. The CMake build copies it there
automatically; if you moved `frontier.exe`, copy `SDL2.dll` (from the SDL2
`lib\x64` directory or the CMake build tree) and the `assets` folder with it.

**`Frontier Engine needs OpenGL 4.5 core; the driver only provides X.Y`.**
The context was created but is too old. Install the current GPU driver from the
vendor site (Windows Update often ships an old one), make sure the game runs on
the discrete GPU on laptops, and avoid remote desktop sessions, which frequently
expose only OpenGL 1.1/3.3. Software Mesa users can try
`MESA_GL_VERSION_OVERRIDE=4.5 MESA_GLSL_VERSION_OVERRIDE=450 ./frontier`.

**`SDL_GL_MakeCurrent failed` / `No usable OpenGL context is current`.**
The window and the 4.5 context were created, but the driver refused to activate
it. The engine no longer treats a *redundant* `SDL_GL_MakeCurrent` as fatal
(context creation already activates the context; some Windows drivers reject the
second call) — if the context works it carries on and logs the version. If the
context genuinely cannot be activated, `frontier --glinfo` prints the video
driver, the displays, the GL strings and the driver limits, which is exactly
what to attach to a bug report.

**The window opens but the scene is black or has no shadows.**
Start with `./frontier --safe-mode`, which disables MSAA, HDR and bloom and uses
a smaller shadow map. Then try `--no-bloom`, `--msaa=1`, `--no-hdr` or
`--render-scale=0.75` one at a time to find the feature your driver dislikes.
The log reports the effective target format and any fallback that was taken.
`--selftest` gives a pass/fail verdict and writes the frame it inspected to
`screenshots/selftest.ppm`.

**Low frame rate.**
Every frame is rendered at `--render-scale` (default 1.0) into an HDR target;
lower it to 0.75 or run with `--safe-mode`. `--view-distance=600` and
`--grass=30000` cut the two biggest costs. The debug panel shows draw calls,
triangles, visible/culled instances and per-pass timings.

**`SDL_CreateWindow failed: Could not initialize OpenGL / GLES library`.**
There is no usable GL driver/display. Confirm with `glxinfo -B` (Mesa utils) or
run on a desktop session. In containers, GPU access must be passed through and
a display server (or EGL/VirtualGL setup) must exist. The engine logs a clear
error and exits with code 1 instead of crashing. Use `--headless` to validate
world generation without a GPU.

**`OpenGL entry point missing: glXxx`.**
The driver does not expose the full 4.5 core set. Update the GPU driver; the
engine requires 4.5.

**Window opens, then `[%s] fragment shader compilation failed`.**
The shader log is printed with the failing file. Check that `assets/shaders`
is next to the executable (CMake copies it post-build) or pass
`--assets=/path/to/assets`. Verify shaders offline with
`scripts/validate_shaders.py`.

**Logs.** Every run writes `frontier.log` by default; `--log-level=debug` adds
placement/input details, `--log-level=trace` is very verbose.

**Screenshots.** `F12` writes a binary PPM (P6) to `screenshots/`. Convert with
ImageMagick (`magick screenshot.ppm screenshot.png`) or ffmpeg
(`ffmpeg -i screenshot.ppm screenshot.png`).
